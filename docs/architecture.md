# Runtime invariants

Pantheon implements [OptChat's pinned specification](https://gist.githubusercontent.com/VictorTaelin/91837951a5ce5b38f341ec1ba1df6449/raw/f51fe5c910427fd6f384d22823140b1693c76207/optchat.md) as a native Rust service. Thoth's interaction design informed the command surface; its Prime Agent runtime is not a dependency.

One channel has one endless memory and one serialized master actor. Different channels run concurrently. Discord ingress, model calls, compaction, background subagents, browser RPC, scheduled checks and outbound delivery have independent workers. One daemon-level lifetime lock protects all operational state, and each memory journal also holds its own lock. Systemd owns restart and process cleanup.

## Memory and request layout

Every master turn takes a settled summary view **before** appending its new input. System instructions and sorted tool definitions are frozen at startup. No date, status, browser URL or task ID enters these fixed prefixes. The provider conversation is fresh per turn. Within a turn, native OpenAI output items (including encrypted reasoning), or Anthropic thinking blocks/signatures, are replayed without reconstructing them. Reasoning is never written to the chat, subagent trace, database or logs. Optional reasoning display is best-effort and bypasses the durable Discord outbox.

Root and worker prompts combine their role/memory protocol with the shared behavior guide in `src/behavior.txt`, followed by the configured operator instructions. The guide covers task ownership, contextual follow-ups, authorization, narrow secret-safe diagnostics, evidence and verification, coding and research practices, delegation and clear progress/results. Requests to act require actual execution rather than a final promise; current tool schemas override obsolete capability claims in chat history. Workers apply the guide to their assigned task, not the whole inherited user request. This text is fixed at startup and introduces no per-turn prefix changes.

Opt-in behavioral checks in `tests/agent_behavior_live.rs` exercise a real authenticated Codex model with controlled tool results. They check username/PATH follow-through, short follow-ups, ordinary conversation and worker task boundaries without executing model-generated commands. Run them with `PANTHEON_TEST_CODEX_MODEL=codex/<model> cargo test --test agent_behavior_live -- --ignored --nocapture`; they consume subscription quota and stay outside CI.

View chunks end at line boundaries before 50k/80k/100k characters. Anthropic receives ephemeral breakpoints on those three pieces and automatic request-end caching. OpenAI API requests receive explicit breakpoints with mode=explicit for GPT-5.6/6 families and implicit request-end caching. Earlier OpenAI models and the Codex subscription backend receive implicit caching only; the Codex adapter strips API-specific cache metadata without changing view content or native reasoning items. No cache keepalive calls or long cache TTLs are used. `/context` shows a recorded-request window grid using provider-reported input, output and cached-token counts, alongside a separate compacted-memory byte grid. Model capacities use explicit display overrides or local Codex metadata. Coordinator usage retains its model identity and is never overwritten by worker search. `/status` reports execution and delivery instead. Raw usage, including cache-write fields when supplied, is retained in the operational database. Local state is never presented as proof of a remote cache hit.

The compactor follows the contextual binary-tree ordering, eight jobs, five size attempts, a 512-byte scale example, shortest answer retention, and ten-second indefinite retries. It receives bare summary text without harness addresses. Short source text forms a free node. A failing compactor holds new turns at the settle barrier; `/stop` cancels the barrier without discarding the user's admitted message.

## Steering and completion

Admission commits each Discord prompt before waking its channel. During a run, the actor reads the durable queue at tool boundaries. It logs exact new input immediately, buffers provider injection until outstanding tool results are complete, and appends the input after the prior native response. This satisfies Anthropic tool-result adjacency and preserves OpenAI reasoning with `context=all_turns`. If steering arrives before an issued tool is executed, the remaining tools get skipped results and the next model request reconsiders them. An already executing tool finishes or is cancelled with `/stop`; arbitrary in-flight side effects cannot be rolled back.

If steering arrives while a final provider response is being generated, that response is emitted as intermediate prose and the agent continues. It receives no final ping. A terminal response is logged first, then its durable chunks and input completion are committed. Only a completion with no outstanding current background work uses the original loop prompt's native reply reference and enables its author's notification. Further prompts steer the loop without replacing that reference. Intermediate prose and activity have no references or notifications. Every send disables automatically parsed mentions. Consecutive presentation events accumulate in a fenced segment with names, IDs, model settings and elapsed tool times; any prose closes the segment and later events open a new fence. Full segments roll over without elision; arguments and outputs remain private. Durable revisions preserve receipts during send/finish races. Delivery runs concurrently across eight channels, with one in-flight item per channel. Activity edits are throttled; new messages can pass delayed edits but cannot overtake unsent earlier messages. Durable input reactions track received, actually submitted, and whole-loop settlement, including steers. A heartbeat renews typing and records unsettled phases, including compaction and detached work. Presentation tables are operational metadata and never enter the model's fixed prefix or canonical memory.

Slash commands run separately from the ingress dispatcher. Browser startup and slow interaction replies therefore do not stop prompt admission. Model/reasoning settings are durable and apply at the next fresh turn; no mid-run schema or system-prefix changes are made.

## Background work

`spawn` accepts named task objects with optional model and reasoning overrides, inherits the parent settings by default, reserves capacity, snapshots settled memory, records all task IDs, and returns immediately after spawning. No foreground mode or waiting tool exists. By default the root has memory, file, shell, browser, web search/fetch, spawn/tell, discovery and wakeup/monitor tools. Its prompt favors direct execution for short tasks, tightly connected steps and verification, with background delegation for substantial independent work, parallel investigations and noisy exploration. Set `agent.coordinator_root = true` for a strict coordinator that lacks file, shell, browser and web execution tools. Explicit existing settings retain their meaning. This startup configuration fixes the root's tool schema for every turn; tools are not dynamically added or removed by task. Spawned workers see the settled channel memory, including prior root tool results, and use zoom/date against that channel's original history. Workers get memory, file, shell, browser, web search/fetch and scheduling tools, plus same-channel discovery and peer messaging, but cannot spawn. Their logs stay under `subagents/`, outside the master's memory. Worker tool calls and inbox notifications never enter the public conversation activity stream; root actions and delivered report markers do. Only their final reports reach the master. Each worker final report immediately produces its own durable inbox message, independently of its spawn batch. Its incoming fence and idle state commit with that message. `tell` commits to the target's durable inbox and delivers at tool boundaries, or resumes an idle worker under the same agent ID in a fresh background turn. A successful master ending does not cancel its children; `/stop` cancels all active work in the channel.

Wakeups and monitors capture their creating agent, channel and authorized requester. Agent tools list and cancel only their own schedules; human slash commands can manage every schedule in their channel. Missed repeating ticks collapse to one wake on restart. Monitors run bounded shell checks independently and wake on changed exit/output, including errors. Output is retained as bounded head/tail text. Unchanged checks do not generate Discord status messages. A monitor is not a webhook listener; this version's monitor watches commands rather than exposing public ingress.

Commands run in the foreground for up to `shell_background_after_seconds` (default 5). A slower command returns a background job ID and keeps running, bounded by `shell_timeout_seconds` (default 3600) and `max_shell_jobs` (default 16). The completion is atomically saved and delivered through the owning agent’s inbox. Both stdout and stderr are drained with bounded head/tail buffers. `/stop` cancels detached commands in the channel and kills their process groups. Monitor commands retain the separate `tool_timeout_seconds` budget.

Initial child reports arrive individually as each worker finishes its current work. A successful turn with running owned shells or queued inbox messages parks the worker, persists its private continuation and releases its permit without delivering a report. Notifications resume that worker under the same identity; once its current work is drained, its report and public incoming marker commit together. Future scheduled intervals do not hold a completed report, and failed turns report their failure immediately. Later shell completions, wakeups, monitor changes and tell messages resume a finished child with the same task, model settings, latest report and a fresh settled main-memory view. Its private trace is retained and event IDs deduplicate logging. Each subsequent final report reaches the parent as a new `[id] report` inbox message. Notifications remain queued if worker capacity is full. Restart recovery reports interrupted commands without replaying them; pending events and schedules survive. Provider conversations, reasoning and unsafe tool effects are not replayed across recovery.

## Agent directory and idle archival

`agent.agent_idle_seconds` defaults to 3600 and applies to workers and channel coordinators. Durable last-activity timestamps update at admission, run start/end and notification delivery. A minute sweep archives idle identities; listing also sweeps before returning. Work that is running or queued prevents archival, including detached shells and pending worker notifications. Future scheduled ticks do not prevent archival. Listing an identity does not refresh its clock. Legacy records receive one grace period on migration because their old timestamps cannot be reliably inferred.

Archival changes directory visibility only. No task, report, private trace, memory, model setting or schedule is deleted. `list_agents` hides archived identities by default; `include_archived=true` includes them. Discovery does not activate an identity. `tell`, wakeups, changed monitor results and user input automatically revive their destination and schedule its model turn. A fresh model turn resumes an idle worker from its task, latest saved report and settled channel view; its full private trace is retained on disk, not replayed as an old provider conversation.

Workers discover and message workers in their own channel. Coordinators can additionally call `list_agents(kind="coordinators")` to discover known neighboring coordinators and use the same `tell` API with a `channel:<id>` target. They cannot directly address another channel's workers. The harness enforces these capabilities and identifies message senders. Directory pages have stable `next_before` cursors and a byte budget to preserve valid JSON within the tool-result cap. Continue with `before` to traverse all entries.

Cross-channel coordinator messages commit to the destination channel's durable inbox and wake its actor immediately, or steer its current run between provider steps. A sleeping destination starts a separate activity with no stale user reply or automatic user ping. Its incoming coordinator marker is visible. Peer messages are work reports, not user instructions. Prompts discourage acknowledgment loops; normal step limits still apply. No automatic request/reply protocol or foreground waiting is introduced.

## Durability and failure boundaries

SQLite WAL with synchronous=FULL stores admissions, outbox receipts, settings, tasks, schedule state and tool intents. Daily JSONL files store the permanent chat and summary tree. User admission provenance makes recovery across the two stores idempotent. Tree summaries are durable even though they are theoretically rebuildable. Back up the entire state directory; stop the daemon or use SQLite's online backup mechanism for a consistent operational database backup. Browser profiles belong in the backup and may contain authentication material.

Restart preserves queued admissions and deliveries. Interrupted turns and subagents receive visible interruption outcomes, and pending tool intents become unknown. Side-effecting tools are never blindly replayed. A reply sent to Discord just before a crash may be sent again after Discord's finite nonce deduplication window: delivery is at least once, not an exactly-once external transaction. Failed delivery remains queued in channel order, without blocking other channels.

Rust handles all orchestration. A packaged Python subprocess is the browser driver bridge to Playwright/Camoufox and websockify; it installs or downloads nothing at runtime. The shared display, window ownership, leases, shared persistent profile and viewer networking are detailed in [browser.md](browser.md).

## Deliberate differences from the reference

- One endless chat per Discord channel rather than a single terminal chat globally.
- Subagents can be used by default for useful independent work, as requested; every invocation remains background-only.
- Kernel file locks replace Unix socket locks. They release on crash without stale lock stealing or PID inference.
- SQLite operational journals replace the reference's post-turn git commit. Canonical log/tree writes retain individual fsync barriers.
- Reasoning display is optional and off by default; reasoning is still retained exactly in the ephemeral provider transcript and never logged locally.
- Model prose is delivered per finished provider step. API providers use complete JSON responses; Codex uses SSE buffered until a complete final response. Ingress and background work remain concurrent during inference. Partial tool arguments are never executed.
- The built-in monitor is a command change watcher; there is no unauthenticated webhook endpoint.

Provider wire contracts were checked against [OpenAI reasoning](https://developers.openai.com/api/docs/guides/reasoning), [Responses reference](https://developers.openai.com/api/reference/resources/responses/methods/create), [Anthropic caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching) and [thinking](https://platform.claude.com/docs/en/build-with-claude/extended-thinking). Model availability and supported effort levels remain provider/account-specific; API failures are surfaced rather than silently switching models.
